# Jurnal Proses — Tugas 6

## Implementasi find_successor
- Kesalahan pertama yang ditemui: Pada implementasi awal, hal yang perlu diperhatikan adalah penanganan wrap-around, yaitu ketika tidak ada ID node yang lebih besar atau sama dengan ID yang dicari, pencarian harus kembali ke node dengan ID terkecil. Tanpa penanganan ini, pencarian dapat menghasilkan node yang salah. 
- Cara memperbaikinya: Fungsi find_successor() mengurutkan ID node, mencari ID terkecil yang lebih besar atau sama dengan ID target, lalu mengembalikan ID node terkecil jika tidak ditemukan. Fungsi juga memeriksa apakah ring kosong sebelum melakukan pencarian.

## Skenario join/leave
- Hasil sebelum dan sesudah node baru bergabung: Sebelum node Medan bergabung, data kurir-test-13 disimpan pada node 136. Setelah node Medan dengan ID 123 bergabung, mapping kurir tersebut berpindah ke node 123. Meskipun lokasi penyimpanannya berubah, proses lookup tetap menghasilkan IP 192.168.1.13.
- Hasil sebelum dan sesudah node keluar: Node Jakarta dengan ID 177 keluar dari ring. Setelah perubahan tersebut, pencarian kurir-001, kurir-002, dan kurir-test-13 tetap menghasilkan alamat IP yang sesuai. Hal ini menunjukkan bahwa data yang diuji masih dapat ditemukan setelah node keluar, meskipun output tidak menunjukkan perpindahan mapping saat node tersebut keluar.
